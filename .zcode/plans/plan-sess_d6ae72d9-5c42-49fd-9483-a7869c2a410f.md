## Goal
A new notebook cell that, for every China-related Wikidata location in `locations_wikidata_info.xlsx`, resolves its CHGIS/TGAZ record and writes a combined Excel output.

## Two-step resolution strategy (verified live)

### Step A — Wikidata P4711 "CHGIS ID" (direct, ~17 of 290 places)
The Wikidata property **P4711** (label "CHGIS ID") stores the TGAZ numeric id; its formatter URL is `https://chgis.hudci.org/tgaz/placename/hvd_$1`. SPARQL query (chunked, 80 QIDs per request, 2s pause between chunks) fetches all P4711 values for the China QIDs in one batch. For each, `tgaz_get(f"hvd_{value}")` fetches the full canonical record.

### Step B — Coordinate matching (the other ~273 places)
No reverse-geocode endpoint exists, so:
1. Search TGAZ by the Wikidata `chinese_label` (as-is). If empty, strip the last char (市/省/县/区/镇) and retry. (Tested: 8/8 matched within 26 km.)
2. Filter results to `year=1800` to pick the historical unit near the end of the Dehergne period.
3. Among the year-1800 records, pick the one whose haversine distance to the Wikidata lat/lon is smallest.
4. **~2s sleep between each live query** (~273 queries ≈ 10 min total) to be polite to the TGAZ server. A progress counter prints every 25 places.

## Output file
`../inferences/wikidata-references/wikidata_chgis_matches.xlsx` — one row per matched location, columns from both sources:

| Group | Columns |
|---|---|
| Wikidata | wikidata_id, english_label, chinese_label, wd_lat, wd_lon, country_label |
| CHGIS | sys_id (hvd_...), chgis_name, transcription, years, feature_type, parent_name, chgis_lat, chgis_lon |
| Match | chgis_source (`wikidata P4711` / `name+coords` / `none`), dist_km, agreement (`agree` <50km, `review`, `no TGAZ coords`) |
